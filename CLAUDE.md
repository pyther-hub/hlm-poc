# hlm-poc

Proof of concept: a small student query encoder (Qwen3-Embedding-0.6B) trained to retrieve against a frozen
teacher document index (Qwen3-Embedding-4B, d=256). Stage A = L2 alignment, stage C = contrastive refinement.
**Experiments run in the three notebooks on Kaggle (GPU T4 x2).** This repo only holds clean, tested functions they
import. Same conventions as tiny-reasoner: flat files, plain functions, no classes, no global state, no config system.
Pruning is out of scope.

## Layout
```
model.py       # load_encoder (hub | dir | "tiny:<seed>"), tokenize, pool_last_token, truncate_normalize, encode, save
data.py        # MS MARCO rows, by-query splits, corpus, alignment queries, CR triples, loaders, JSON/emb I/O, resolve_cfg
teacher.py     # embed_main (sharded, resumable), merge_shards, fp16_sanity, time_embedding, halve_sizes
losses.py      # LOSSES registry: l2, cosine, contrastive, hybrid
train.py       # ALIGN_DEFAULTS, CR_DEFAULTS, train_loop, run_stage, align_main, cr_main, LR_SCHEDULES, benchmark_scaling
evaluation.py  # retrieve_topk, METRICS, compute_metrics, teacher_ceiling, evaluate_dir, summarize_runs, measure_latency
ddp.py         # copied verbatim from tiny-reasoner; keep the API identical
notebooks/     # GENERATED by scripts/make_notebooks.py; edit cells there, never the .ipynb
scripts/       # make_notebooks.py, run_notebooks_tiny.py
tests/         # CPU, offline, tiny random Qwen3 + GPT-2 tokenizer
README.md      # HLD + API reference + cfg tables. Update it when a public function or cfg key changes.
```

## Environment
- Always use the project venv: `.venv/bin/python`, `.venv/bin/python -m pytest`. Never system python, never another env.
- Install with `uv pip install --python .venv/bin/python <pkg>` and add it to `requirements.txt`.
- Local machine is a Mac (CPU). Never load the real 0.6B/4B models or run real training locally; use `tiny:<seed>`.
  Downloading a tokenizer alone to check its behaviour is fine.

## After EVERY edit
```
.venv/bin/python -m pytest -q                    # ~25 s, must stay < 30 s
```
After changing notebook cells or anything they call:
```
.venv/bin/python scripts/make_notebooks.py && .venv/bin/python scripts/run_notebooks_tiny.py
```
Do not report a change as done unless these pass.

## Rules
- Every result-affecting knob lives in a notebook control panel and in the stage's defaults dict
  (`ALIGN_DEFAULTS`, `CR_DEFAULTS`, `TEACHER_DEFAULTS`). Nothing result-affecting hard-coded in a module.
- Stages communicate only through directories (weights, cfg.json, train_log.jsonl, metrics.json).
- `train_loop` stays one explicit top-to-bottom function: no Trainer, callbacks or hooks.
- Losses / lr schedules / metrics are small functions in registries; each new one gets a test.
- Every loop honours `debug` (3 steps, shape printing, grad check). Non-finite loss always raises.
- DDP: workers live in .py files with signature `(rank, world_size, cfg)`; print/save only on rank 0; every rank hits
  the same collectives; `reduce_mean` for logged metrics.
- New module or model change → test in `tests/`: shape, gradient, overfit-one-batch.
- Docs and notebooks use `from model import ...`, never `import model`.
- Data provenance: `negative_passages` are NOT verified to be BM25. Don't claim they are.
